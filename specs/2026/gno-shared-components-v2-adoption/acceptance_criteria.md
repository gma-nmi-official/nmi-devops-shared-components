# Acceptance criteria: repository adoption

## Adoption acceptance

1. The registered path, Git identity, branch, HEAD, remote state, and dirty tree
   are recorded from direct inspection.
2. Repository-local instructions and their impact on future work are recorded.
3. Languages, frameworks, dependency tooling, architecture, test strategy, CI,
   and operational gaps are described without claiming unobserved capabilities.
4. Pre-existing user changes remain untouched.
5. Product unknowns are explicit and no development authorization is inferred.
