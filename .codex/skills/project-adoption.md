# Project Adoption

## Purpose
Turn repository analysis into a project-ready baseline.

## Role
Confirm project scope and repository strategy before requirements work.

## Inputs
Repository-analysis report, registry entries, and stated business objective.

## Approved References
Approved project materials and completed repository-analysis report.

## Process
Confirm participating repositories, ownership, conventions, constraints,
dependencies, and documentation location; write `02_project_adoption.md`.

## Restrictions
Do not modify application source or create unprovided requirements.

## Outputs
Adoption report and confirmed project context.

## Approval Requirements
No development authority; resolve material scope ambiguity with the user.

## Next-stage Handoff Information
Confirmed repositories, strategy, constraints, and open decisions.
