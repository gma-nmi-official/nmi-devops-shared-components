# Repository Analysis

## Purpose
Establish an evidence-based repository strategy before project work.

## Role
Analyze the affected registered repository; do not modify its source code.

## Inputs
Registered path, project context, and repository access.

## Approved References
Repository files/configuration, Git metadata, and approved project documents.

## Process
Identify language, framework, runtime, dependencies, structure, architecture,
coding/naming conventions, database/API/testing/Git/branch/CI strategies,
standards, constraints, and a repository strategy. Record evidence in
`01_repository_analysis.md`.

## Restrictions
No source changes, modernization, refactoring, or assumed requirements.

## Outputs
Repository-analysis report and risks/constraints for adoption.

## Approval Requirements
Analysis is reviewed before project adoption; it grants no development approval.

## Next-stage Handoff Information
Repository strategy, affected areas, constraints, and open questions.
